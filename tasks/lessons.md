# Lessons


- 当仓库同时存在 src/preload/index.ts 和遗留的 src/main/preload.js 时，新增桥接 API 不能只改一处，必须确认运行时真正加载的 preload 实现并同步更新。
- 当用户明确收敛“本机配置”和“远端设备配置”的边界时，要立即回头检查数据模型里是否错误引入了 `deviceKey` 一类跨设备维度，避免把本地触发器映射做成全网集中映射。
- 当快捷键录制与对话框复用同一个按键事件时，不能只依赖子组件的 preventDefault；对于 Escape 这类会被对话框框架拦截的键，需要在 Dialog.Content 层显式拦截，避免误关闭弹框。

- 当 `apply_patch` 连续报 `windows sandbox: setup refresh failed` 时，先把它当成工具侧工作区刷新故障处理，不要反复硬撞同一补丁；改用 PowerShell 做定点替换，比继续重试补丁更稳。
- 当用脚本批量替换 TSX 结构时，不要只看替换结果的外观，必须额外检查是否多留了孤立的大括号或断开的 JSX 结构；先做尾部语法扫描，再跑构建验证。
- 当仓库已经提供现成的 Dialog / AlertDialog / Select 封装时，不要先新增一层业务包装再去替换页面；应直接复用现有封装，避免多出无意义的中间组件。

- 当 Windows 环境下的 `apply_patch` 同时改多个文件且带绝对路径时，如果 UI 出现“已拒绝”并伴随 `windows sandbox: setup refresh failed`，先拆成单文件、相对路径的小补丁重试；至少我这次就是 `executor.ts` 用相对路径后立即成功，而不是代码内容本身有冲突。
- 当某个文件反复被 `apply_patch` 卡在 sandbox refresh，而另一个文件已经能正常补丁时，不要继续把它们绑在同一个补丁里；应切换成 PowerShell 的定点读写完成该单文件修改，然后立刻回读文件确认没有转义污染或格式损坏。
- 当用 PowerShell 直接写 Markdown 或代码片段时，here-string 的 `@"` 头后面不能跟任何字符，且反引号会参与 PowerShell 转义；写入后必须立即回读检查，避免出现这次 `todo.md` 里反引号被污染成控制字符的情况。
- 当运行时错误已经给出明确符号名或函数名时，首轮排查不要再用 `keyboard`、`mouse`、`scene`、`trigger` 这类宽词做全仓搜索；先查唯一标识，沿最短调用链只读局部代码，否则搜索结果会把方案文档、UI 文件和历史 spec 无意义地卷进上下文。
- 当列表页同时存在“当前选中项”和“新建态”时，不能只用空 id 表示新建；必须显式维护 `isCreatingNew` 之类状态，否则自动回填首项的 effect 会把刚清空的表单又覆盖回去。
- 当页面被放进父级 `overflow: hidden` 的全高布局里时，新面板不能只写 `h-full overflow-auto`；左右列和真正滚动主体都要补 `min-h-0`，否则内容会撑满但滚动条不生效。

- 当一个页面同时承载“查看执行”和“配置编辑”两类任务时，不能用同一套信息布局硬兼容；要尽早拆出 `view/edit/create` 模式，查看态紧凑可执行，编辑态完整可配置，否则信息密度和交互边界都会失控。

- 当多个页面都要展示同一类运行日志时，日志监听不能绑在页面组件里；要上提到 App 级订阅并落到共享 store，否则切页就会漏日志，跨页面也无法同步显示。

- 当仓库已经有统一的 `Select` 封装时，弹框里的筛选下拉不要再手写一套 Trigger/Content 的边框、尺寸、箭头样式；优先回到封装默认样式，只在必要处补尺寸，否则局部弹框里最容易出现样式漂移。

- 当共享 UI 封装既要兼容“传纯文本 children”又要兼容“外部手动传 `ItemText`”两种用法时，应在封装层做兼容判断，不要只靠业务页面约定统一，否则很容易在不同页面出现重复渲染和布局错位。
